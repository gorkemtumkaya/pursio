# Changelog
- Keep CHANGELOG.md in the project root, in "Keep a Changelog" format.
- When a spec task or feature is finished, add an entry under "## [Unreleased]" in the right group: Added, Changed, Fixed or Removed.
- One line per change, written for a user, not a developer: what changed and why it matters. Reference the spec name, e.g. "(spec: skill-path-ui)".
- Don't log refactors, tests or typo fixes unless they change behavior.
- Never rewrite existing entries.
